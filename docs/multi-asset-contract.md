# MultiAssetResearchV1 (1.0.0)

The additive 1.1.0 schema in `contracts/multi-asset/v1.1` uses the same contract name and adds `unadjusted_price`. The matching result schema is in `contracts/multi-asset-result/v1.1`. Consumers choose a whitelisted version before validating. Unadjusted non-FX observations retain source facts but cannot produce total/rolling return, investment cash or benchmark performance even if completeness flags are true. All 1.0.0 schema bytes and fixtures remain unchanged. See [official data behavior](taiwan-official-data.md).

This additive JSON interface does not change ResearchSignalV1, MarketRegimeV1 or BacktestResultV1. Producer: chain_survey. Numerical service: invest_backtest. No cross-repository Python imports.

Required request keys: `contract="MultiAssetResearchV1"`, `schema_version="1.0.0"`, `as_of` (timezone-aware cutoff), `base_currency`, `objective` (`accumulation`/`income`), `periods_per_year` (12 or 252), `period_grid` (sorted unique ISO dates), `risk_free_rate` (annual decimal or null), `rolling_windows` (integer array), `instruments`, `observations`, `distributions`, `fx_rates`, `regimes`, `cash_flow_assumptions`.

Each instrument has `instrument_id`, `symbol`, `name`, `asset_type` (`stock`,`etf`,`fx`,`benchmark`), `exchange`, `quote_currency`, `domicile`, `management_style` (`passive`,`active`,`none`), `benchmark_id` (string/null), `return_basis` (`total_return_index`,`split_adjusted_price`), `distributions_complete` (boolean), `corporate_actions_complete` (boolean). Optional `expense_ratio` (annual decimal), `expense_ratio_available_at` (timezone timestamp), `fx_base_currency` and `fx_quote_currency` for an FX instrument. Unknown attributes are null rather than guessed. FX quote units must match quote_currency; spot FX excludes carry/leverage.

Every observation: `instrument_id`, `period` (grid date), `value` (positive finite number/null), `published_at`, `acquired_at`, `source_url` (HTTP/S), `snapshot_id`. Timestamp fields may be null for an explicitly unusable row. Availability is max(published_at, acquired_at), never economic period alone. For duplicate instrument/period vintages, use the latest eligible availability and reject ambiguous equal-time values. Endpoints with missing/noneligible values never form a return. Price and total-return-index semantics come from the instrument. For split-adjusted prices, a complete same-basis distribution history is required to claim total return; split/corporate-action coverage must also be explicit. Null observations retain visible quality issues.

Each distribution: `instrument_id`, `ex_date`, `pay_date` (ISO date/null), `amount_per_unit` (nonnegative finite), `currency`, `distribution_type` (`income`,`capital_gain`,`return_of_capital`,`unknown`), plus the same four provenance fields (`published_at`,`acquired_at`,`source_url`,`snapshot_id`). Amount is on the same split-adjusted unit basis as prices. Deduplicate by instrument/ex/pay/type and eligible vintage. Total return uses ex-date amounts once. Paid cash uses pay_date; unknown pay dates never become cash. Total-return indices already include distributions: never add them again. Return of capital is displayed separately and never called earned income.

Each FX row: `period`, `base_currency`, `quote_currency`, `rate` (positive finite/null) plus provenance. `rate` quote units buys one base unit. Use exact date direct/inverse conversions only; no hidden forward fill or triangulation. Both total-return endpoints need FX rates. Cash uses pay-date FX. Identity conversion is 1. FX instrument levels are spot levels of their declared base/quote pair and are not an investment earning interest.

`cash_flow_assumptions`: `initial_capital` (positive reporting-currency amount), `withholding_tax_rate` (decimal/null), `distribution_fee_rate` (decimal/null), `fx_fee_rate` (decimal/null), `buy_fee_rate` (decimal/null), `reinvest_fee_rate` (decimal/null). Explicit zero means known zero, null means unknown. Net cash/terminal wealth requiring an unknown assumption is null with reasons. Simple uniform withholding is a user scenario, not a jurisdiction tax engine. No capital-gain liquidation tax assumption is invented. NAV already reflects expense ratio; do not deduct it twice. Market-price income accounting is not possible from a normalized total-return index alone.

`regimes`: existing MarketRegimeV1 records, with source freshness unchanged. Assign using only records available at interval START (not period-end), same market when a market is declared, and ignore stale regimes. Both the original as_of date and UTC availability date must equal the interval start date, with availability timestamp no later than start; late historical snapshots never become current regime labels. No carried or future labels. Empty or insufficient regimes produce unavailable segment metrics.

Optional request fields handled by the main product: `holdings` (snapshots with instrument_id, period, provenance and positions), `evidence` (dated, sourced independent scenario rows linked to an instrument, indicator, driver, sensitivity and model). Holding position: `security_id`, `weight` in [0,1], `sector` (string/null), `currency` (string/null), `factors` (mapping factor name to loading). Unknown weight mass remains explicit. Snapshot weights do not become revenue or EPS sensitivities. Evidence timing classes stay relative to their declared target; catalog narratives are not observations.

Result: `contract="MultiAssetResultV1"`, `schema_version="1.0.0"`, `as_of`, `base_currency`, `objective`, `input_sha256`, `instruments` (array with identity, `metrics`, `unavailable`, `returns`, `rolling_returns`, `cash_flows`, `quality`), `correlations` (array), `methodology` and `quality`. CLI hashes exact input bytes. Main product must validate matching input hash and identities before displaying output. All JSON numbers finite; undefined statistics serialize null with reasons. Correlations disclose common sample size, full/train/OOS and regime results; no correlation promotes a driver or supplies an unvalidated financial beta.
